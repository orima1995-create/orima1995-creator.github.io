# VINTAGE ALARM — STAGING QA

## 公開ルール

- デザイン・構造・文章の重要変更は、まずstagingで確認する。
- mainへ直接実装しない。
- stagingの実URLをスマホで目視し、採用された変更だけmainへ反映する。
- OWNER'S NOTE完成画像・コピーは、明示指示なしに加工・再生成・全文リライトしない。

## スマホ目視監査

最低確認幅：

- 320px
- 360px
- 390px（基準）
- 430px
- 768px前後

見る項目：

- 横スクロールがない
- ヘッダーとメニューが片手で押せる
- 主要タップ対象は概ね44px以上
- TOPの最初の画面でタイトル・コピー・次の入口が過度に離れない
- OWNER'S NOTESの完成画像が一覧性のために小さくなりすぎない
- 日本語本文を16px未満へ安易に落とさない
- 長文の行間・行長が詰まりすぎない
- DEEP DIVE画像とキャプションの対応が一目で分かる
- YouTubeが横にはみ出さない
- 200%拡大でも重要情報が欠けない
- キーボード操作時のfocus表示が消えない
- reduced motion設定時に不要な動きを抑える

## 画像

- 原本を保持する。
- WebP / AVIF等の軽量版は派生ファイルとして作る。
- OWNER'S NOTEの文字・時計輪郭は容量だけで採否を決めない。
- 実機目視で劣化が気にならないことを採用条件にする。
- LCP候補画像はlazy loadingの使い方を個別に確認する。

## 文章QA / natural-japanese

参考：coji/natural-japanese

このサイトでは自動リライト装置として使わない。

適用対象：

- AIが新規作成・補助したHISTORY本文
- AIが新規作成・補助したDEEP DIVE本文
- 説明文・検索descriptionなど、AI生成比率が高い文章

原則対象外：

- 完成済みOWNER'S NOTE
- ユーザー自身の意図的なリズム・言い回し
- 引用文

運用順：

1. 資料・実機・Webで事実を確認する。
2. SITE_RULES.mdに従って文章を作る。
3. natural-japanese系の観点でAI臭・均質さ・翻訳調・過剰な接続を検出する。
4. 指摘を一件ずつ「直す / 残す」で判断する。
5. 事実の確信度を上げる方向の書き換えはしない。
6. 全段落を均一に整えない。
7. stagingでユーザー確認後にmainへ反映する。

特に避ける事故：

- 「つまり」「面白いのは」「〜と言えるだろう」で意味を勝手に付ける
- 全見出しを同じ文型へ揃える
- 全段落を同じ長さへ均す
- 本文にない因果を接続詞で作る
- 未確認事項を自然な物語で埋める
- OWNER'S NOTEのキャッチをDEEP DIVEで説明・回収する
